# Nexus AI Improvement Framework

## Goal

Give Nexus a set of generic, working tools for inventorying, measuring, testing, and safely upgrading the AI parts of *whatever project is open* - not tied to any one project's AI stack or vocabulary.

## What's implemented

Each module below is a real, working main-process file (no placeholders), wired into `preload.js` (as `window.nexus.aiFw*`) and `main.js` (as `ai-fw-*` IPC channels), with a UI in the "AI Tools" panel (🧠 in the sidebar, or "Open AI Tools" in the command palette).

- **`aiInventory.js`** - scans the active project for AI models, required API keys, config files, and guardrail files in use. Read-only.
- **`aiMetrics.js`** - records and summarizes real AI call metrics (latency, cost, success/failure) per project, persisted to `.nexus-ai-metrics.json` in the project folder.
- **`aiGuardrailTester.js`** - finds and runs a project's own guardrail/contract/safety/compliance npm scripts and reports real pass/fail results and a score.
- **`aiUpgradeOrchestrator.js`** - applies a literal find/replace to one config file (e.g. swapping a model identifier), then keeps the change only if the project's own guardrail tests and lint script still pass - otherwise it rolls back automatically.
- **`promptTesting.js`** - lets a project keep named prompt variants and record quality scores against them over time.
- **`dependencyAuditor.js`** - checks installed vs. latest version for AI-related npm dependencies (best-effort; degrades gracefully offline).
- **`complianceMonitor.js`** - turns the guardrail run history into a compliance status (latest score, trend, logged violations).
- **`changelogGenerator.js`** - filters a project's real git history down to commits that touch AI-related files or mention AI-related terms.
- **`knowledgeBase.js`** - a small cross-project store (`~/.nexus-ai-knowledge-base.json`) for lessons learned, so patterns carry forward into the next project.
- **`experimentationFramework.js`** - side-by-side (A/B) comparison of two variants using real recorded numeric observations, with a conservative "insufficient data" / "no clear difference" / "clear difference" verdict.

### Live-metrics auto-instrumentation

`aiMetrics.recordMetric()` no longer needs to be called by hand for Nexus's own AI usage. Every real call Nexus itself makes - through `callNim`/`callNimForProjectGeneration` (NVIDIA NIM) and `callGemini` in `main.js` - is now timed and recorded automatically, including real token counts read back from each provider's own API response (`usage.prompt_tokens`/`completion_tokens` for NIM, `usageMetadata` for Gemini) when the provider reports them. Calls tied to an open project are recorded against that project's `.nexus-ai-metrics.json`; calls with no project open yet (the general Ask Gemini box, project generation before the folder exists, changelog generation) fall back to Nexus's own userData folder so nothing is silently dropped. This is the data everything below depends on.

### AI guardrails wired into the Ship pipeline

The Ship tab's real AUDIT → REPAIR → TEST → GATE pipeline (`runPipeline()` in `renderer.js`) now has a GUARDRAILS stage between Test and the gate: it runs the project's own guardrail/contract/safety npm scripts (via `aiGuardrailTester`) automatically on every pipeline run, and a failing guardrail suite fails the overall gate exactly like a failing test does. A project with no guardrail scripts gets a SKIPPED stage, never a fabricated pass. Separately, the Pipeline query panel's PowerShell-style DSL (`pipelineEngine.js`) gained two new read-only cmdlets, `Get-GuardrailResult` and `Get-AIMetric`, exposing the same already-persisted history for ad-hoc querying (e.g. `Get-GuardrailResult | Where-Object passed -eq false`) - consistent with that module's deliberate "no side effects, only ever reads data handed to it" design.

- **`aiRecommendations.js`** - a short, prioritized list of concrete recommendations derived from fixed thresholds on aiMetrics/complianceMonitor/dependencyAuditor's real recorded data (e.g. a model failing >20% of at least 5 calls, a regressing compliance trend, dependencies behind latest). Every recommendation carries a `basis` field showing exactly which real numbers produced it. Nothing here is generated by an AI model.
- **`aiAlerts.js`** - real trend-based alerts: compares the most recent 10 recorded calls per model against the 10 before that, and flags a real drop in success rate or jump in average latency past a fixed threshold. Deliberately not machine-learning "prediction" - it's arithmetic over two real windows of already-recorded calls, and a model without enough history to form two windows is skipped rather than given a guessed trend.
- **`aiCostOptimizer.js`** - real dollar costs from real recorded token usage. Never hardcodes or guesses provider pricing (it changes over time and getting it wrong would mislead real spending decisions) - instead it asks you to record your own current per-model price once (`setPricing`, USD per 1M tokens, input/output priced separately), persisted to `.nexus-ai-pricing.json`, then multiplies that against real recorded token counts. A model with no pricing set is listed as unpriced, never estimated.
- **`aiPerformanceTuner.js`** - real p50/p90/max latency per model, computed from `aiMetrics.getLatencyPercentiles()` (actually recorded call latencies only, models with fewer than 5 samples excluded rather than given a misleading single-sample percentile), plus which reliable (≥90% success) model is currently fastest.

## Design notes

- Every module operates on real files/processes in the active project folder. None of them fabricate data - a project with no guardrail scripts gets `hasGuardrails: false`, not an invented score.
- Guardrail tests and lint run via `execFile` with an argv array (no shell), consistent with the rest of Nexus's process handling.
- `aiUpgradeOrchestrator` refuses to touch any path outside the project folder, and only ever does a literal (non-regex) substring replace.
- None of this is specific to any one project's AI stack, model names, or terminology - `aiInventory`'s model-detection patterns are generic (Gemini, Claude, GPT, NVIDIA NIM, local/Ollama), and the guardrail/config file matchers look for common naming conventions, not one project's specific file names.

## Possible next steps

- A metrics/compliance trend chart in the AI Tools panel (currently JSON-only output for every module, including the newer Recommendations/Alerts/Cost/Performance sections).
- A "suggested next experiment" helper that reads `knowledgeBase` entries to propose what to A/B test next.
- Scheduling `aiAlerts.getTrendAlerts()` to run automatically in the background (e.g. once per launch) and surface a badge, instead of only on demand when the AI Tools panel is opened.
- Extending live-metrics auto-instrumentation beyond Nexus's own NIM/Gemini calls to cover AI calls made by whatever *target project* is open, if it exposes a consistent call site to hook - this would need to be opt-in per project since Nexus doesn't own that code.
